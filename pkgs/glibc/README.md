# glibc для Linux ABI SynapseOS

Пакет предоставляет динамический загрузчик и библиотеки GNU C Library для x86_64.
Совместимость с приложениями glibc определяется поддержкой Linux ABI ядром и
проверяется отдельно для каждого класса программ.

Исходник: ветка `release/2.44/master`, коммит
`045c51476c7abf6144815a4db44f51a118b4cb3e` из
[зеркала GNU Toolchain](https://gitlab.com/gnutools/glibc).
SHA-256 закреплённого архива:
`5894b65628630090f3267df50d2cfb7edc700daf75fb91df7d881d5eb4e327f7`.
[Публичный профиль зеркала](https://github.com/gnutools/glibc) называет его
копией исходного репозитория Sourceware. Прямое сравнение с Sourceware Git
в этой среде не выполнено из-за защиты сайта. Код архива и контрольная сумма
проверены отдельно.

В исходнике проверено наличие исправлений `GLIBC-SA-2026-0022` и `0023`
в `elf/dl-load.c`, а также `GLIBC-SA-2026-0015` в `libio/fileops.c`.
`GLIBC-SA-2026-0024` затрагивает оптимизацию Power8, которую пакет x86_64
не собирает. `nscd` отключён при конфигурации. Это проверка известных
на 21.10.2026 исправлений, а не утверждение об отсутствии других уязвимостей.

Сборка выполняется командой `make glibc SDK=<путь-к-SDK>` из корня репозитория.
Нужны GCC, GNU make, `bsdtar`, `jq`, `dpkg-deb` и проверяемый архив исходников.
Рецепт загружает закреплённые по SHA-256 host-инструменты GNU awk и заголовки
Linux UAPI в локальный каталог сборки. Он не зависит от заголовков Linux хоста.

Пакет устанавливает загрузчик `/lib/ld-linux-x86-64.so.2`, все собранные
динамические библиотеки `lib*.so*` из `/lib`, включая NSS, модули преобразования
кодировок из `/usr/lib/gconv`, таблицу псевдонимов и исходные данные локалей.
Карты символов распакованы при сборке, поэтому `localedef` не требует `gzip`
в гостевой системе.
Локали `en_US.UTF-8` и `ru_RU.UTF-8` заранее скомпилированы в отдельные каталоги
`/usr/lib/locale`. Утилиты `locale` и `localedef` лежат в `/bin`, glibc-версия
`getconf` лежит в `/usr/libexec/glibc/getconf`, чтобы не подменять базовую
утилиту musl. Отладочные символы исполняемых файлов снимаются при упаковке,
динамические символы и версии символов сохраняются. Общий архив локалей,
`nscd` и все дополнения upstream glibc в пакет не входят.

Заголовки, стартовые объектные файлы и библиотеки для линковки находятся в
отдельном пакете `glibc-dev` под `/usr/share/glibc/sysroot`. Они не заменяют
заголовки musl в `/usr/include`. Для программы с glibc нужен отдельный выбор
этого sysroot и интерпретатор `/lib/ld-linux-x86-64.so.2`; простая установка
`glibc` не переключает системный компилятор с musl на glibc.

Проверенная сборка runtime и файлов разработки из корня репозитория:

```sh
make glibc-dev JOBS=2
```

На хосте `smoke.c` из `glibc-dev` скомпонован с изолированным sysroot. ELF
получил интерпретатор `/lib/ld-linux-x86-64.so.2` и версии символов `GLIBC_*`.
При запуске через собранный загрузчик результат `GLIBC_SMOKE_PASS`.

В отдельной видимой QEMU VM с ядром SynapseOS 0.1.948 и пакетом glibc 2.44.0-r6
тот же ELF запущен через QEMU Guest Agent командой `/tmp/glibc-smoke-r6-final`:
код завершения 0, вывод `GLIBC_SMOKE_PASS`. Проверены TLS, pthread, локали
`C`, `en_US.UTF-8`, `ru_RU.UTF-8`, файл, TCP через loopback, поиск `localhost`
через NSS, внешний DNS для `synapseos.ru` и динамическая загрузка `libm`.
`/bin/locale -a` показал обе UTF-8 локали, команда
`/bin/localedef --no-archive -i de_DE -f UTF-8 /tmp/de_DE.UTF-8` завершилась
с кодом 0. Сервис `stats` работал, а запрос из гостя к
`https://synapseos.ru` вернул HTTP 200. Для внешнего DNS потребовалась
поддержка системного вызова `sendmmsg` (307) в ядре.

Проверка не подтверждает работу произвольных приложений glibc, всех локалей,
`nscd` и полного набора upstream glibc.
