# AyuGram Desktop

```sh
make ayugram JOBS=2
```

Экспериментальный порт AyuGram Desktop 7.2.9 для SynapseOS, musl и Weston
Сам клиент и tde2e собираются из исходников, Qt и прочие библиотеки берутся из закреплённых APK
Архивы исходников и их SHA-256 перечислены в `port.json`
Версии инструментов сборки закреплены в `build-packages.lock`
Зависимости запуска и их SHA-256 перечислены в `assets.json`

Для сборки на Linux нужны bubblewrap, разрешённые пользовательские пространства имён
и обычные инструменты из корневого README репозитория
Root-доступ и Docker не требуются, окружение Alpine создаётся в `pkgs/.work/ayugram-source`
Индексы и APK проверяются штатным apk, проверка TLS не отключается
Обвязка пакета использует Make и shell, штатные генераторы AyuGram используют Python внутри Alpine

Пакет заменяет экспериментальный `telegram-desktop` в каталоге пакетов
AyuGram основан на Telegram Desktop, но является отдельным клиентом
Требуется ядро не ниже 0.1.915 с операцией `FUTEX_WAKE_OP`
Клиент собран с собственными реквизитами приложения и запущен в Weston
Окно клиента и выбор русского языка проверены
Пользователь подтвердил успешный вход в аккаунт в тестовой VM

## Как получить реквизиты для собственной сборки

Эти действия выполняет владелец приложения, собирающий свой клиент
Пользователю готового клиента с действующим API ID создавать приложение не требуется

1. Подготовьте действующий аккаунт Telegram в официальном приложении
2. Откройте [my.telegram.org](https://my.telegram.org), введите номер и пройдите вход
3. Перейдите в **API development tools** и заполните форму своего приложения
4. Сохраните полученные `api_id` и `api_hash` локально по инструкции ниже
   Если приложение уже создано, используйте его реквизиты из этого же раздела

На основном компьютере подготовьте файл вне репозитория:

```sh
umask 077
mkdir -p "$HOME/.config/synapseos"
touch "$HOME/.config/synapseos/telegram-api.env"
chmod 600 "$HOME/.config/synapseos/telegram-api.env"
```

Откройте файл `~/.config/synapseos/telegram-api.env` в текстовом редакторе
Добавьте две строки, заменив текст в кавычках своими значениями:

```sh
TDESKTOP_API_ID='значение api_id'
TDESKTOP_API_HASH='значение api_hash'
```

`api_id` должен содержать число, `api_hash` содержит 32 шестнадцатеричных символа
Не публикуйте файл в Git, не прикладывайте его к отчётам и не выводите значения в журнал сборки
Код входа в аккаунт и пароль двухэтапной проверки в этот файл не записывают
Это реквизиты приложения, они не заменяют последующий вход пользователя в Telegram

## Сборка и запуск

Рецепт читает файл `~/.config/synapseos/telegram-api.env`
Имя файла сохранено для совместимости с первым этапом подготовки
Другой путь можно задать через `TELEGRAM_API_FILE`
Реквизиты передаются в CMake через окружение, тестовый API ID не используется
Вывод сборки скрывает значения API ID и API hash
Каталог исходников и сборки имеет права 700, CMake cache остаётся внутри него
Не публикуйте этот каталог, в нём находятся параметры компиляции с реквизитами

Проверить только формат и права доступа к файлу, без сетевых запросов и компиляции:

```sh
ROOT="$PWD" BUILD_ROOT="$PWD/pkgs/.work" OUT="$PWD/out" SDK="$PWD/.sdk" \
  bash pkgs/ayugram/source-build.sh --check-credentials
```

Сообщение `AYUGRAM_CREDENTIALS_VALID` подтверждает локальную проверку
Действительность API ID на сервере проверяется только при работе самого клиента

```sh
make ayugram JOBS=2
# Для файла в другом месте
make ayugram JOBS=2 TELEGRAM_API_FILE="$HOME/.config/synapseos/telegram-api.env"
```

Для локальной сборки можно передать обе переменные окружения прямо в Make,
без файла `telegram-api.env`:

```sh
TDESKTOP_API_ID=ВАШ_ID TDESKTOP_API_HASH=ВАШ_HASH make ayugram JOBS=2
```

Обе переменные обязательны; если они заданы, файл не читается. При использовании
собственных секретных реквизитов учитывайте историю команд оболочки. Для выпуска
клиента используйте собственный API ID, как требует Telegram.

В SynapseOS запустите `weston`, затем из его терминала:

```sh
ayugram
```

Библиотеки клиента находятся в `/usr/lib/ayugram/runtime`
Qt и его частный LLVM устанавливаются отдельными пакетами
Лаунчер использует Wayland и программную отрисовку по умолчанию
Системные библиотеки Weston не заменяются

## Проверка фоновых задач

```sh
ayugram-async-probe
```

Проверка запускает 32 вложенные задачи, проверяет 32 элемента последовательной очереди
и дожидается завершения её обработчика
Ожидаемый результат: `AYUGRAM_ASYNC_PASS`
Проверка прошла на хосте и в KVM с ядром SynapseOS 0.1.915

Для `crl::async` используется пул потоков Qt через поддерживаемый патч сборки
Обычная глобальная очередь libdispatch 6.1.2 в тестовой VM не выполняла фоновые задания
Qt также требует `FUTEX_WAKE_OP`, добавленный в ядре 0.1.915
Без него семафоры не пробуждали главный поток при подготовке фото и видео
После установки исправлений на ядре 0.1.915 пользователь подтвердил успешную повторную
проверку фото, видео и предпросмотра вложений без зависания окна
Это подтверждение относится к проверенным пользователем файлам

## Проверка встроенного SQLite

Для встроенной копии SQLite выбран штатный режим `unix-dotfile`, как в отдельном пакете SynapseOS
Настройка передаётся через CMake, импортированные исходники SQLite не изменяются
Проверка использует ту же копию SQLite из архива AyuGram:

```sh
ayugram-sqlite-probe
```

Она создаёт отдельную базу в `/tmp`, проверяет транзакции, откат, повторное открытие,
русский текст и отказ второму писателю, затем удаляет свою временную базу
Проверка прошла на хосте и в отдельной KVM VM с ядром SynapseOS 0.1.912
В обоих случаях получено `AYUGRAM_SQLITE_PASS` с кодом завершения 0

При запуске Qt сообщает об отказе создать контекст OpenGL, окно работает с программной отрисовкой
Аппаратное ускорение этим запуском не подтверждено
Переписка, передача файлов, звук, звонки и WebView пока не проверены
Не считайте успешную сборку подтверждением этих возможностей
Тестирование проводится на отдельном образе QEMU с мониторингом на synapseos.ru
Личные сессии, пароли и коды входа в пакет не включаются

Ограничение тестовых реквизитов описано в
[документации Telegram](https://core.telegram.org/api/obtaining_api_id)
Исходный клиент: [AyuGram Desktop](https://github.com/AyuGram/AyuGramDesktop)
