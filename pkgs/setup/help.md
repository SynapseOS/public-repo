# Пакетный менеджер setup

Сначала загрузите актуальный каталог, затем выберите пакет:

```sh
setup update
setup ls
setup ls -u
setup search nano
setup info nano
setup install nano
```

`setup update` обновляет каталоги, а `setup upgrade` — установленные программы.
`setup ls` показывает доступные пакеты, `setup ls -u` — ещё не установленные,
`setup ls -i` — установленные. Длинные команды `list --not-installed`
и `list --installed` тоже поддерживаются.
`sbase` и `ubase` устанавливаются целиком, со всеми входящими утилитами.

```sh
setup upgrade --dry-run
setup upgrade
setup upgrade darkhttpd
setup remove nano
setup reinstall sbase
setup verify
setup verify sbase
```

`reinstall` повторно устанавливает доступную версию уже установленного пакета,
восстанавливая его файлы. Если пакет удалён, используйте `install`.
Локально изменённые файлы конфигурации сохраняются; новая конфигурация может
оказаться рядом с суффиксом `.setup-new`. Проверяйте её перед заменой своей.
`verify` сравнивает файлы с базой пакетов; изменение конфигурации вручную
может быть ожидаемым отличием.

`--dry-run` показывает план установки, обновления или удаления.
`--yes` подтверждает выполнение без вопроса. Зависимости подбираются автоматически.

Репозитории описаны в `/etc/setup/repos/*.json`, открытые ключи —
в `/etc/setup/keys/*.pub`. Посмотреть подключённые источники:

```sh
setup repo list
```

После добавления источника выполните `setup update`. Каталог подписан,
архивы проверяются по SHA-256. Для проверки срока действия каталога нужно
корректное системное время. Ошибка истёкшего индекса требует новой публикации
со стороны владельца репозитория.

Если установка была прервана и `setup` сообщает о незавершённой транзакции:

```sh
setup recover
setup verify
```

База установленных пакетов находится в `/var/lib/setup`, кеш —
в `/var/cache/setup`. Не удаляйте базу для исправления ошибки: она нужна
для восстановления и учёта владельцев файлов.

## Ядро и загрузчик

Ядро обновляется отдельным официальным пакетом:

```sh
setup update
setup upgrade kernel --yes
```

`/boot` должен быть смонтирован загрузчиком системы. `setup` проверяет наличие
`/boot/syngitf.txt`; тип файловой системы и имя устройства не используются для
этой проверки. При обновлении меняются `commit=` и `version=` в маркере,
а `root=` и остальные настройки этого компьютера сохраняются.

Версия ядра помещается в `/boot/boot/kernels/<версия>/kernel`, и в
`/boot/boot/limine/limine.conf` добавляется запись загрузки. Предыдущие ядра
и записи остаются доступны. Файлы загрузчика Limine этим пакетом не заменяются.
Запись загрузочных файлов проверяется чтением и SHA-256; при прерывании
транзакции выполните `setup recover` перед следующей установкой.

Новое ядро начинает работать после перезагрузки. Сохранение запущенных процессов
при переходе на новое ядро сейчас не поддерживается.

## Автоматическое обслуживание

`setup auto` восстанавливает незавершённую транзакцию, обновляет подписанный
каталог и все установленные пакеты, затем переустанавливает пакеты с отсутствующими
или повреждёнными файлами. Изменённые пользовательские конфиги сохраняются.
Ошибки подписи, нехватка места и небезопасные типы файлов останавливают команду.
Обновлённое ядро требует обычной перезагрузки; команда сама её не выполняет.
`setup auto --dry-run` показывает план по сохранённому каталогу без записи.

Для старого setup: `setup update`, `setup upgrade setup --yes`, затем `setup auto`.

## Аккаунт и подписка Plus

Обновите setup обычной командой:

```sh
setup update
setup upgrade setup --yes
setup auth
```

`setup auth` показывает ссылку `https://synapseos.ru/lk/login`. Войдите в кабинет
с выданным логином и паролем, нажмите «Получить код входа в setup» и введите
12-значный код в запросе `One-time login code:`. Код действует 10 минут и
используется один раз; при вводе он не отображается. Пароль аккаунта остаётся
в браузере. Не передавайте код или сессию в аргументах команд.

```sh
setup auth status
setup update
setup ls
setup install ИМЯ_ПАКЕТА
setup auth logout
```

В setup могут входить обычные клиенты без Plus. Каталог Plus подключается
к аккаунту автоматически, но пакеты доступны только при активной подписке.
Каждая установка setup получает отдельную сессию: выход на одном компьютере
не отключает другие. В кабинете можно завершить все сессии. Смена пароля или
отключение аккаунта отзывает доступ со всех компьютеров.

Сессия хранится в `/etc/setup/auth/plus.token` с правами 0600. Каталог описан
в `/etc/setup/repos/plus.json`. Проверяются TLS, отдельная подпись Ed25519
каталога Plus и SHA-256 архивов. Сессия не попадает в URL и вывод команд.

Plus доступна организациям и физлицам. До указанной даты включительно
(по Москве) доступны все пакеты каталога. После окончания подписки
установленные файлы и база пакетов сохраняются; новые загрузки, переустановка
и обновления Plus закрываются. Обычные репозитории продолжают обновляться.
Сохранённый каталог не обходит проверку подписки. Продление возобновляет
доступ по сохранённой сессии, если её не отозвали.

Без соединения с сервером операции с каталогом Plus останавливаются.
Установленные программы работают; `setup ls -i`, `setup verify` и удаление
пакетов доступны без обращения к Plus. `setup auth logout` отзывает эту сессию
на сервере и сохраняет установленные программы. Для локального отключения
каталога без сети предусмотрена `setup plus disable`; чтобы отозвать
серверный доступ, завершите сессии в кабинете.

## Проверка обновлений при загрузке

Init запускает `setup check` отдельным процессом через 15 секунд. Проверка
не задерживает запуск ОС, не читает ввод и не устанавливает пакеты.
В консольном режиме появляется краткое предложение `setup upgrade`;
результат также сохраняется в `/var/lib/setup/updates.txt` и показывается
при запуске `setup` без аргументов, включая терминал графической сессии.
Журнал: `/var/log/setup-updates.log`. Нет сети или setup занят —
проверка завершается, запуск системы продолжается.

Отключение в `/etc/settings.ini` (также поддерживается cloud override):

```ini
[Setup]
CheckUpdates = 0
```

Ручная проверка: `setup check`. Установка: `setup upgrade`.
Скачивание показывает объём, среднюю скорость и время; при известном
размере — процент и оставшееся время. В терминале отображается полоса
прогресса, в журнале — строки без управляющих символов.
