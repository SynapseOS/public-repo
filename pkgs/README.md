# Рецепты пакетов

Сборка всех пакетов из корня репозитория:

```sh
make all JOBS=4
```

Один пакет и его зависимости:

```sh
make sqlite
make -C pkgs/mindustry-desktop
```

Список целей: `make list`. Проверка рецептов: `make check`
Требования к хосту, устройство SDK и CI описаны в [корневом README](../README.md)

`port.json` хранит закреплённые URL и контрольные суммы, `manifest.json` задаёт
пакет и зависимости исполнения. Специальные шаги находятся в `recipe.sh`
Патчи upstream применяются с `--fuzz=0`, исходные архивы проверяются по SHA-256
Python-сборщики заменены Makefile и shell-рецептами

Обычные порты собираются статически с musl, графика и JNI используют общие
библиотеки musl. Библиотеки glibc хоста не должны попадать в целевые пакеты
Архивы создаются в `out/` относительно корня репозитория
Успешная компиляция не является результатом гостевого теста

Пакет `go` содержит официальный компилятор, собранный из исходников закреплённым
bootstrap Go. `go-runtime` устанавливает исходники стандартной библиотеки,
заголовки ассемблера и базу часовых поясов для linux/amd64 без cgo
Go использует штатный clone(CLONE_VM | CLONE_VFORK), требуется поддержка ядра
Runtime Go включается в каждую программу при линковке, отдельной общей библиотеки нет
Обёртка `/bin/go` задаёт GOROOT, CGO_ENABLED=0 и GOTOOLCHAIN=local,
если пользователь не установил их явно. Кросс-компиляция и cgo в этом наборе не проверены

```sh
make go caddy JOBS=2
```

Caddy собирается из закреплённого исходного архива. Модули проверяются средствами
Go по upstream go.sum, сборка выполняется с `-mod=readonly`
Тестовый конфиг `/etc/caddy/Caddyfile` обслуживает HTTP на порту 8080,
отключает административный API и автоматическую выдачу TLS-сертификатов
После установки служба `caddy` запускает этот конфиг автоматически

```sh
go run /usr/share/go/examples/probe.go
caddy version
caddy run --config /etc/caddy/Caddyfile --adapter caddyfile
```

`gitea` и `prometheus` упаковывают закреплённые статические бинарные выпуски
разработчиков. Рецепты проверяют SHA-256 архивов, но пока не собирают эти два
сервера из исходников. Для Gitea нужен пакет `git`. Конфигурация находится в
`/etc/gitea/app.ini`, данные в `/var/lib/gitea`. В образах Cloud и Extended служба
изначально выключена, а конфиг разрешает соединения только с `127.0.0.1`
Для доступа извне укажите `HTTP_ADDR` и `ROOT_URL`, затем включите службу:

```sh
service enable gitea
service status gitea
```

Первый администратор создаётся в мастере настройки. Пакет не содержит учётных
данных для входа

Prometheus запускается службой с конфигурацией `/etc/prometheus/prometheus.yml`
и хранит данные в `/var/lib/prometheus`. Пакет `synapse-exporter` отдаёт метрики
CPU, памяти, процессов, сети и корневой файловой системы на порту 9100. Для каждого
PID доступны имя, резидентная память, память контекста ядра и накопленное время CPU.
Общие страницы входят в память каждого использующего их процесса, поэтому сумма RSS
может превышать фактический расход системы. Prometheus собирает
их с `127.0.0.1:9100`, а свой интерфейс предоставляет на порту 9090

```sh
service status synapse-exporter
service status prometheus
curl http://127.0.0.1:9100/metrics
curl 'http://127.0.0.1:9090/api/v1/query?query=synapse_exporter_collect_success'
```

Перед резервным копированием остановите Gitea и Prometheus, чтобы базы и журнал WAL
не менялись во время чтения. Архив создаёт штатная команда `backup`:

```sh
service stop gitea
service stop prometheus
backup create /root/server-data.tar --root / etc/gitea etc/prometheus var/lib/gitea var/lib/prometheus
backup test /root/server-data.tar
service start prometheus
service start gitea
```

На целевой системе остановите службы и восстановите архив в пустой каталог:

```sh
service stop gitea
service stop prometheus
mkdir /tmp/empty-restore
backup restore /root/server-data.tar /tmp/empty-restore
```

Проверьте содержимое и перенесите конфигурацию и данные в соответствующие каталоги
целевой системы, затем запустите службы

Если Gitea ещё не инициализирована, каталога `/var/lib/gitea` нет, и его нужно
исключить из списка путей. В KVM архив с базой и репозиторием Gitea и данными
Prometheus восстановлен в отдельной VM. SHA-256 базы совпал с исходным, Gitea
отдала страницу репозитория, а Prometheus перешёл в состояние готовности

Пакет `restic` предоставляет отдельное зашифрованное резервное копирование. В KVM
проверены `init`, `backup`, `snapshots` и `restore` для локального репозитория;
восстановленный файл совпал с оригиналом по SHA-256. Храните пароль вне репозитория
и передавайте его через `--password-file`. Удалённые хранилища пока не проверены.
SynapseOS возвращает пустой список расширенных атрибутов файлов, поэтому restic не
сохраняет атрибуты, которые система не предоставляет через `listxattr`

Пакет `alertmanager` содержит сервер и `amtool`. В Cloud и Extended служба выключена
до настройки получателя. Начальный маршрут `local-placeholder` не отправляет
уведомления. После настройки `/etc/alertmanager/alertmanager.yml` включите службу
командой `service enable alertmanager`. Сервер слушает только `127.0.0.1:9093`;
кластерный режим выключен. В KVM проверены готовность HTTP и приём оповещения через API

Пакеты включены в Cloud и Extended. CI обнаруживает их через `manifest.json`,
выполняет `make check` и собирает вместе с остальными пакетами через `make all`
