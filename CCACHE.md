# Кэш компилятора для SynapseOS

## Для чего нужен ccache

`ccache` сохраняет результаты отдельных компиляций C/C++. При следующей сборке он может вернуть объектный файл из кэша, если исходник, заголовки, параметры компилятора и версия компилятора совпадают. Это ускоряет повторную компиляцию после переключения ветки или удаления объектных файлов.

Кэш не заменяет сборочную систему и не хранит готовые результаты всех рецептов. Шаги настройки и сборки внешних проектов через CMake, Meson, Ninja и другие инструменты всё ещё выполняются, хотя вызовы компилятора из них могут попасть в кэш.

Изменённый исходный файл или заголовок формирует другой ключ и компилируется заново. Изменение только комментария обычно тоже меняет ключ и вызывает компиляцию.

## Где хранится кэш

Сборки из корней `public-repo` и `kernel` настроены на общий каталог:

```text
/workspace/synapseos/.ccache
```

Максимальный размер настроен на 30 ГиБ. Когда лимит достигается, ccache автоматически удаляет старые записи, а не исходники или результаты текущей сборки.

Проверить размер и попадания:

```sh
CCACHE_DIR=/workspace/synapseos/.ccache ccache -s
```

Сбросить только статистику, сохранив содержимое:

```sh
CCACHE_DIR=/workspace/synapseos/.ccache ccache -z
```

Очистить весь кэш вручную, если это действительно нужно:

```sh
CCACHE_DIR=/workspace/synapseos/.ccache ccache -C
```

Команда `-C` удаляет закэшированные объекты и заставит будущие компиляции выполнить работу заново. Не запускайте её между обычными сборками без необходимости.

## Использование

После установки ccache команды сборки остаются прежними. Для публичного репозитория:

```sh
make -C /workspace/synapseos/public-repo check
make -C /workspace/synapseos/public-repo native APPS="init/ sh/" JOBS=4
```

Для ядра:

```sh
make -C /workspace/synapseos/kernel kernel JOBS=4
```

`/usr/lib/ccache` добавляется в PATH сборок, поэтому вызовы `gcc`, `g++` и других поддерживаемых компиляторов проходят через ccache. Обёртка SDK `sdk/apps/apps/common/musl-cc` также использует общий каталог.

Чтобы проверить, что ccache установлен:

```sh
command -v ccache
ccache --version
```

## Перенос кэша на другую машину

Каталог `.ccache` находится вне Git-репозиториев и не отправляется в GitHub. Чтобы повторно использовать его на другой машине, перенесите каталог вместе с рабочими деревьями, например через `rsync`, затем проверьте `CCACHE_DIR` и свободное место. Если путь отличается, задайте его в окружении перед сборкой:

```sh
export CCACHE_DIR=/путь/к/.ccache
```

На новой машине могут отличаться компилятор, системные заголовки или параметры. Для безопасности ccache учтёт их как отличающиеся входы и выполнит компиляцию заново. Это нормальное поведение.

## Ограничения

- Кэшируются вызовы компилятора, а не произвольные результаты сборочных сценариев.
- Объектные файлы, созданные до подключения ccache, не добавляются в кэш автоматически.
- Переключение веток не очищает `.ccache`; одинаковые входы могут повторно использовать объектные файлы.
- Изменённые входы не используют устаревший объект: они компилируются заново.
- Для команд, которые вызывают компилятор по абсолютному пути или обходят PATH, кэш может не применяться. Проверяйте счётчики `ccache -s`.
- Кэш предназначен только для ускорения. Его удаление не повреждает исходники и не меняет корректность сборки.
